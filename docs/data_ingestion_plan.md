# 判決書資料 10,000 筆抽樣匯入雲端 Neo4j 實作計畫 (data_ingestion_plan.md)

本文件為 10,000 筆判決書隨機比例抽樣匯入任務的設計與實作計畫存檔。

## 1. 資源與風險評估

在執行大量匯入前，我們針對 Neo4j AuraDB Free（免費版）進行了資源佔用評估，以確保系統在免費額度內安全運作：

### AuraDB Free 限制
- **節點上限**：200,000 個
- **關係上限**：400,000 條

### 10,000 筆資料預估佔用
- **預估總節點數 (Nodes)**：約 **50,000 ~ 60,000 個**
  - 10,000 個 `Judgment` 節點。
  - 約 40,000 個 `Section` 段落節點（平均每篇切割 4 段）。
  - 約 5,000 ~ 10,000 個去重後的 `Person`（關係人）與 `Law`（引用法規）節點。
  - *佔總額度約 **25% ~ 30%***。
- **預估總關係數 (Relationships)**：約 **103,000 ~ 110,000 條**
  - 40,000 條 `HAS_SECTION` 關係。
  - 約 63,000 條角色與法條引用關係（`DEFENDANT`、`PLAINTIFF`、`CITED` 等）。
  - *佔總額度約 **25% ~ 28%***。

**結論**：此 10,000 筆抽樣方案非常安全，能在維持測試數據多樣性的同時，為後續 Graph RAG 的相似度關聯分析預留 70% 的充足空間。

## 2. 抽樣數據比例規劃

依據 `data/202604/` 目錄下共 100,427 筆判決書的母體案件大類比例進行隨機抽樣：

* **民事案件 (60.38%)**：**6,038 筆**
* **刑事案件 (35.59%)**：**3,559 筆**
* **行政案件 (3.86%)**：**386 筆**
* **其他案件 (0.18%)**：**17 筆**
* **總計**：**10,000 筆**

## 3. 實作腳本設計 (`import_sample.py`)

為了執行此計畫，我們於 `scripts/import_sample.py` 實作了專屬抽樣匯入腳本：
1. **目錄分類**：遍歷 `data/202604/` 目錄，將所有 JSON 檔案依資料夾名稱（民事、刑事、行政、其他）歸入四大列表。
2. **隨機抽樣**：對四大列表分別進行 `random.sample`，抽出對應比例的筆數。
3. **並行寫入優化**：為加速寫入，引入 Python 的 `ThreadPoolExecutor` 開啟多個 Workers 進行並行寫入，以克服雲端資料庫連線的網絡延遲。
